A fix for agents that couldn't find the host.

## Fixes

- On a host with Docker (or another network bridge) running, Orbit could advertise itself over mDNS on the bridge's
  address instead of the LAN's, and agents found no host. It now prefers network cards over bridges and tunnels.
  Agents pick the address they search from the same way.

## Files

| File | For |
|---|---|
| `orbit-host-0.1.1-linux-x64.zip` | The host, on the Sunshine machine (Linux, x64), with its own Java runtime |
| `orbit-agent-0.1.1-linux-arm64.zip` | The agent on a Raspberry Pi or other ARM64 Linux client, with a Java runtime |
| `orbit-agent-0.1.1-linux-x64.zip` | The agent on an x64 Linux client, with a Java runtime |
| `orbit-agent-0.1.1-windows-x64.zip` | The agent on Windows 10/11, with a Java runtime |
| `orbit-agent-0.1.1.zip` | The agent for clients that have Java 25 already |
| `SHA256SUMS` | Checksums: `sha256sum -c SHA256SUMS` |

## Install

The host's fix is what matters; updating agents is only needed on clients that run Docker or other bridges.

- **Host:** unzip, then run `./orbit-host/install-host.sh` in your desktop session. It quits the running Orbit and
  keeps your settings.
- **Linux client with a desktop:** unzip, then `./orbit-agent/install-agent.sh`.
- **Linux client on a text console** (e.g. a Pi without a desktop): unzip, then `./orbit-agent/install-agent-tty1.sh`.
- **Windows client:** unzip, then `powershell -ExecutionPolicy Bypass -File install-agent.ps1` in the folder.

Each installer updates in place and keeps the agent's settings.
